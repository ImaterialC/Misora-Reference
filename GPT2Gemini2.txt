## **2. Catatan teknis terakhir**

**A. Quick Edit dan multi-segment — penting**

Saya menemukan satu masalah konseptual yang belum sepenuhnya dijawab.

Pada `core/story_ast.py`, `Box.clean_text` dibentuk dengan menggabungkan `seg_texts` tanpa pemisah:

```
parts = [s for s in self.seg_texts if s]return game_to_xuat("".join(parts))
```

Akibatnya, bila satu Box mempunyai empat segmen, Quick Edit yang hanya menampilkan satu string gabungan tidak memiliki informasi yang cukup untuk menentukan pembagian segmen baru setelah pengguna mengedit teks secara bebas.

Snapshot-based Undo saja tidak menyelesaikan masalah ini.

Saran saya: Quick Edit tetap sederhana secara visual, tetapi Box multi-segment harus menyediakan area edit per segmen. Semua segmen diedit sebagai satu transaksi dan tetap mempertahankan `voice_cue`, `kind`, `raw_breaks`, `extra_args`, serta struktur aslinya.

Referensi: [core/story_ast.py](https://github.com/ImaterialC/Misora-Editor/blob/main/core/story_ast.py?utm_source=chatgpt.com#L254-L315)

**B. Virtualized Card Pool — mekanisme scroll**

Gemini sudah memilih arsitektur yang benar. Tetapi ada satu hal yang harus ditentukan: bagaimana pengguna melakukan scroll isi kartu yang mempunyai empat baris atau lebih, sementara seluruh kartu hanya memiliki tinggi tiga baris?

Scroll isi kartu tidak boleh bertabrakan dengan scroll daftar All Script.

Tentukan pemisahan gesture yang jelas, misalnya wheel untuk daftar dan kombinasi keyboard/gesture khusus untuk scroll isi kartu aktif. Tidak perlu scrollbar terlihat.

**C. Pengukuran 54d harus berbasis pixel**

Jangan mengandalkan `tk.Text(width=54)` untuk menjamin lebar persis 54 digit-width.

Nilai `width` pada Tkinter Text adalah ukuran karakter berdasarkan metrik font widget, bukan jaminan lebar pixel sebesar 54 digit dari ruler.

Gunakan hasil pengukuran pixel dari helper 54d untuk menentukan lebar container kartu. Pertimbangkan border dan padding agar area teks benar-benar konsisten. Ini berlaku juga untuk Import from XUAT.

**D. Pin Speaker — identitas dan batas navigasi**

Gemini sudah menetapkan bahwa rename saat Pin aktif tidak mengubah speaker target. Pastikan implementasinya menggunakan variabel identitas tersendiri, misalnya `_pinned_speaker_name`, bukan mengambil ulang isi `speaker_var` setiap kali Next/Prev ditekan.

Selain itu, istilah *chapter* harus didefinisikan. Apabila satu `StoryDocument` adalah unit navigasi, gunakan batas current document secara eksplisit agar tidak muncul asumsi pembatas bab yang tidak tersedia di AST.

**E. Insert ketika Box 0 aktif**

U-01 sudah benar menolak Box 0 sebagai target Replace. Namun, Insert ketika Box 0 sedang aktif juga harus ditentukan: rekomendasi saya, Box baru dimasukkan sebelum Box dialog pertama.

**F. XUAT — Treeview tetap perlu pengisian bertahap**

Memindahkan scan ke worker akan menyelesaikan pekerjaan berat klasifikasi, tetapi mengisi ribuan item Treeview dalam satu operasi main thread juga bisa membekukan UI.

Isi daftar dalam beberapa batch kecil melalui main-thread queue processor. Progress queue sebaiknya terbatas atau menggabungkan update progress yang lama agar tidak menambah antrean tanpa batas.

**G. S12 — jangan membaca konfigurasi mesin pengguna dalam tes**

Ada dua tes yang perlu perhatian:

- `test_phase3_performance_config::test_05` saat ini dapat fallback membaca `misora_config.json` lokal.
- `test_s9c_workspace_safety::test_04` mengharapkan `misora_config.default.json` tersedia.

Perbaikan tes harus menggunakan template bersih atau fixture sementara milik tes. Jangan membaca konfigurasi pengguna sebagai fallback dan jangan memulihkan atau menimpa file lokal untuk memaksa tes lulus.

## 2. Additional Implementation Contracts to Include in S10

### A. Multi-Segment Quick Edit

The existing `Box.clean_text` concatenates segment text without a delimiter.

Therefore, a single flattened text field cannot reliably reconstruct original segment boundaries after arbitrary editing.

Do not claim that snapshot-based Undo alone guarantees lossless multi-segment editing.

Please define a segment-aware Quick Edit interaction. Recommended approach:

- Single-segment Box: one simple plain editor.
- Multi-segment Box: expose each segment as a separate plain editable area/row inside the Quick Edit tab.
- All segment edits commit as one logical Box transaction.
- Preserve original segment ownership and ordering.
- Preserve `speaker`, `voice_cue`, `kind`, `raw_breaks`, and `extra_args`.
- Use complete `BoxSnapshot` old/new state for Undo/Redo.
- Preserve immutable JP source keys and Translation Lock.

The interface can remain visually simple without flattening the underlying AST.

### B. Virtualized Card Pool Internal Scrolling

Define how a user scrolls content inside a fixed 3-line card without a visible scrollbar while still scrolling the overall All Script list.

The two scroll behaviors must not conflict.

Specify the exact mouse-wheel, keyboard, or modifier gesture contract, then test:

- Outer list scrolling.
- Active card internal scrolling.
- Cards with 4+ lines.
- Focus changes.
- Widget recycling while a card is internally scrolled.

### C. Pixel-Exact 54d Geometry

The `tk.Text(width=54)` option is not a reliable implementation of a pixel-calibrated 54 digit-width boundary.

Use the shared 54d measurement helper to calculate the actual pixel width of the card/container, accounting for border and padding.

Apply the same width contract to:

- Virtualized All Script cards.
- Import from XUAT paired dialogue fields.
- Import metadata and Actor/Speaker fields.

Add tests with both supported dialogue font presets and the relevant Windows DPI settings.
