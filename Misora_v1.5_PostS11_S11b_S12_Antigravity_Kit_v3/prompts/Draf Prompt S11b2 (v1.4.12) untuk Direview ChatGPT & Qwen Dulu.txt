PART 2 — EXACT TECHNICAL SPECIFICATIONS (`Q-02b`)
==================================================

### 1. Strict `Q-01` Data-Safety Boundary & Case-Insensitive Exclusion Alignment
- Route ALL XUAT sync file discovery AND writes strictly through the canonical **`Translation\en\Text`** boundary (`resolve_xuat_text_roots` semantics supporting all 6 concrete path forms including `<GameRoot>\src\BepInEx\Translation\en\Text`) and ALL `Q-01` exclusions:
  - 5 official XUAT rule exclusions (case-insensitive `endswith`): `.font.txt`, `.resizer.txt`, `postprocessors.txt`, `preprocessors.txt`, `substitutions.txt`.
  - All legacy exclusions (case-insensitive): `.missing.txt`, `.report.txt`, `_summary.txt` (fixing the old uppercase `_SUMMARY.txt` mismatch in `xunity_sync.py`), `_warnings.txt`, and `.bak_`.
- **Hard Data-Safety Guarantee:** `Translation\en\Other`, `Translation\en\RedirectedResources`, `Translation\ja\Text`, arbitrary `Text/` dirs, rule files, and `.bak_` files MUST NEVER be scanned or modified during Save.
- Do NOT maintain a divergent copy of exclusion rules; reuse `core.xuat_index` helpers read-only (via DI or local lazy import) and verify filename-exclusion parity in unit tests.

### 2. Match-Semantics Preservation (`norm_search` vs `normalize_xuat_key`)
- **CRITICAL:** `XUnitySyncManager` currently matches keys using `core.story_ast.norm_search()` (which performs `game_to_xuat()`, NFKC, dash normalization, whitespace collapse), whereas `XuatIndex` uses `normalize_xuat_key()` (which also strips NGUI tags and unescapes). These are **NOT identical**.
- **Binding Rule:** Preserve **`norm_search()`** matching semantics during the single-pass batched sync (do NOT silently switch sync matching to `normalize_xuat_key()` or blindly write through `XuatIndex` without parity).
- Prove zero behavioral drift with an explicit **old-vs-new match-set parity test** covering keys with NGUI tags (`[FF0000]...[-]`), `{playername}` / `{0}`, extra whitespace, fullwidth/halfwidth case, and escaped newlines (`\n`).

### 3. Cache Freshness & Stale-Disk Safety
- Define and enforce an explicit freshness strategy in `/plan`:
  - **Preferred clean default:** Perform **EXACTLY ONE fresh strict `Translation\en\Text` scan per save** (reading eligible `.txt` files once for the entire batch of $B$ modified boxes, NOT $2 \times B$ scans) — guaranteed 100% fresh against external edits while dropping 20-box complexity from $40 \times F$ disk scans to $1 \times F$ (and $0$ scans when no boxes were modified).
  - If any in-memory cache is reused across saves, it MUST validate freshness (file list + `mtime_ns`/size or SHA-256 `file_fingerprints`) before trusting cached line numbers so external edits are NEVER clobbered or missed.

### 4. Single-Pass Batched Per-Key & Per-File Sync Architecture
Design clean batched methods on `XUnitySyncManager` (while preserving backward-compatible `preview_matches()` / `find_and_update()` wrappers for existing direct unit tests):
1. **Batch Key Preparation:** Resolve each modified box's immutable JP source key via `box.uid` + `orig_jp_map` (identical to existing S10 contract).
2. **Same-JP-Key / Different-New-EN Conflict Detection:** If multiple modified boxes in the same save share the same normalized JP key (`norm_search`) but carry **DIFFERENT** new English translations, surface this as an **explicit conflict** (e.g., included in the conflict confirmation / skipped with explicit warning) — NEVER silently depend on iteration order to overwrite one box's translation with another's!
3. **Single-Pass Batch Match & Conflict Gate:**
   - Scan eligible `Translation\en\Text` files **AT MOST ONCE** for all unique target JP keys in the batch, collecting every `(file_path, line_index, raw_key, current_val)` match.
   - Preserve the existing conflict preview/confirmation gate whenever a key matches multiple files/lines with differing existing translations (batching the confirmation cleanly instead of spamming per-box modals).
4. **Grouped Per-File Atomic Update (<= 1 Read/Backup/Write Per Target File):**
   - Group all confirmed line replacements by `target_file_path`.
   - For each affected `.txt` file: read/decode strictly, apply all line updates for that file in memory (preserving exact raw key whitespace, escaped single-line multiline value, comments, untouched lines, encoding, BOM, and CRLF/LF), create **AT MOST 1 backup**, and write via **`write_atomic_encoded` AT MOST ONCE** per save call.
5. **Secondary-Sync Failure Tolerance & Duration Telemetry:**
   - Preserve `test_s2_dirty_contract::test_07`: if secondary XUAT sync raises or fails on any target file, primary bundle/file save stays `True`/clean and unsynced `_modified_boxes` remain retained for retry.
   - Log exact XUAT sync elapsed duration in `[XUAT Sync]` (e.g., `Synced N box(es) across M XUAT file(s) in X.XXXs (scanned K files)`) so Project Lead can directly measure real-tree duration in Windows QA.
