## 2. S10 — Critical `BoxSnapshot.raw_breaks` Editing Safety

I inspected the current AST implementation.

Relevant source:
- `core/story_ast.py::BoxSnapshot.from_box()`
- `StoryDocument._records_from_snapshot()`
- `StoryDocument.replace_box()`

`BoxSnapshot.from_box()` stores each segment's current `Seg.raw` into `raw_breaks`.

`_records_from_snapshot()` uses `raw_breaks[k]` as the record text for non-linebreak values, rather than necessarily using the updated `seg_texts[k]`.

Therefore, changing `seg_texts` while retaining stale `raw_breaks` can cause Quick Edit to write old segment text back into the document.

This is a critical data-integrity concern.

Please explicitly define how S10 constructs the post-edit snapshot:

1. Capture the complete original `BoxSnapshot`.
2. Collect edited text separately for each segment.
3. Update the new snapshot's raw representation consistently with the edited segment text and document break conventions.
4. Preserve the exact number and ordering of segments.
5. Preserve `speaker`, `voice_cue`, `kind`, and all `extra_args`.
6. Record complete old/new snapshots for one logical Undo operation.
7. Verify that the resulting `StoryDocument.records` actually contain the edited text.

The test MUST go beyond comparing snapshots:

- Verify the edited segment content in underlying AST records.
- Undo and Redo.
- Serialize to binary.
- Load the binary back.
- Compare all segment contents and metadata.
- Confirm voice cue and command structure remain intact.

Because `core/story_ast.py` is forbidden in S10, use the existing AST APIs. If the current API cannot satisfy the new Quick Edit contract without core changes, STOP and report the required core dependency. Do not modify forbidden files.

1. Applied entries.
2. Duplicate entries.
3. Dialogue right-side value matching.
4. Shared speaker matching.

The current `XuatEntry` model does not expose an explicit Actor/Dialogue category field.

Therefore, simply changing the final shared-speaker branch to exclude rows is insufficient.

Please define and implement a deterministic Actor/Speaker exclusion strategy that executes BEFORE any entry can be inserted into `analysis.candidates`.

Requirements:

- Protect known Actor/Speaker source-key and translation identities.
- Apply the protection before the Applied, Duplicate, and right-side matching passes.
- Actor entries must never appear as cleanup candidates, even unchecked.
- Entries ambiguous between a dialogue match and a speaker/actor match must be excluded from destructive cleanup.
- Duplicate Actor/Speaker entries must remain protected.
- Actor/Speaker XUAT entries must remain available to the Import matching functionality.
- Do not classify arbitrary dialogue entries as Actors based only on a filename assumption without verifying the repository's actual XUAT structure.

If the current XUAT data model cannot reliably distinguish a global Actor dictionary from ordinary dialogue entries, explicitly document the reliable identification source and conservative fallback. Do not silently claim that all global Actor entries are protected without a testable classification rule.

Add tests for:
- Normal Actor source/value match.
- Same Actor source key duplicated across multiple files.
- Same translation value used as both Actor name and dialogue.
- Actor entry appearing in an Applied or Duplicate pass.
- Regular dialogue still eligible for archiving.
- Actor import matching still functional.
