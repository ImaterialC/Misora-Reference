### 1. `U-11` — Deterministic Pre-Pass Actor/Speaker Protection (`core/xuat_cleanup.py`)
Because `XuatEntry` does not expose an explicit Actor/Dialogue category field, simply changing the final shared-speaker branch in `classify_cleanup_candidates()` is INSUFFICIENT.
Implement a **deterministic Actor/Speaker exclusion gate that runs BEFORE ANY entry can be inserted into `analysis.candidates`**:
1. **Build Protected Actor Identity Sets Up Front:** Before running the Applied, Duplicate, and Right-Side Dialogue passes, build deterministic protected sets of:
   - Known Actor/Speaker source normalized keys (from the document's speakers, original JP speaker keys, and any explicitly provided `protected_actor_keys` / `protected_actor_values` derived from the document/import speaker lookup), AND
   - Known Actor/Speaker translation values (normalized/exact values of known actors in the document/import).
   - Do NOT classify arbitrary dialogue entries as Actors based solely on an unverified filename assumption; explicitly verify and document the reliable identification source and conservative fallback in `/plan` and `PROJECT_STATE.md`.
2. **Pre-Pass Enforcement Across ALL Passes:**
   - Apply the protection filter BEFORE inserting any entry from the **Applied**, **Duplicate**, or **Right-Side Value Matching** passes.
   - Actor/Speaker entries MUST NEVER appear in `analysis.candidates` (ZERO rows — NOT even unchecked `uncertain` rows).
   - Duplicate Actor/Speaker entries sharing a protected source key across multiple XUAT files MUST remain completely protected.
   - Any entry ambiguous between a dialogue translation and a known Actor/Speaker name/value MUST be excluded conservatively from destructive cleanup.
3. **Preserve Import Availability:** Actor/Speaker entries MUST remain 100% intact and queryable in `XuatIndex` for `Import from XUAT` matching.

### 2. `U-09` & `U-14` — Redesigned, Document-Identity-Guarded `Import from XUAT` Dialog (`misora.py::ImportFromXUATDialog`)
- **Document Identity & Structural Integrity Guard (CRITICAL — Never Trust Positional Indices Alone):**
  - At `ImportFromXUATDialog` construction, capture:
    1. Stable document identity / generation token (`doc` object identity / doc revision token),
    2. Document path (`file_path`),
    3. Target Box UIDs and original JP keys for every planned dialogue/actor update,
    4. Metadata identity/source information (original Box 0 Title, Subtitle, Synopsis).
  - Before executing `_on_apply_import()`:
    1. Verify the **exact same document** is still active (`self.app.current_doc` matches captured identity & path),
    2. Verify every target **Box UID** still resolves to the intended Box in that document,
    3. Verify the document has not been structurally replaced or reloaded.
    4. If ANY identity check fails, abort safely before mutating anything and notify the user to reopen `Import from XUAT`.
- **Remove `Include Actor` Checkbox & Exclude Box 0 Dialogue Row:**
  - Remove the legacy `Include Actor` checkbox completely.
  - Exclude `Box 0` from ordinary dialogue rows.
- **Dedicated Metadata & Unique Actor Section (Top of Review List):**
  - Display paired read-only rows for:
    1. **Title** (`1` row -> updates Box 0 Title via existing metadata model API),
    2. **Subtitle / Outline** (`1` row when present -> updates Box 0 Subtitle via existing metadata model API; **strictly preserve Synopsis/Summary** unless separately and explicitly selected for import),
    3. **Unique Actors / Speakers** (`1` row per unique speaker name in the document, with `<` / `>` duplicate switcher and Skip checkbox -> applies to all unlocked dialogue boxes matching that speaker name; locked boxes are skipped and clearly reported).
  - Ordinary Dialogue rows appear below with clear Locked / Skipped / Conflict / Missing indicators.
- **Uniform Pixel-Exact `54d` Geometry:**
  - Size ALL paired read-only text containers using the canonical S09 Nunito Bold `54d` reference pixel helper (+ explicit border/padding allowance; NEVER rely on `tk.Text(width=54)`):
    * Title, Subtitle, and Unique Actor rows: fixed **`1 line × 54d` pixel width**.
    * Ordinary Dialogue rows: fixed **`3 lines × 54d` pixel width**.
  - Container pixel width MUST stay consistent when switching between `Global — Nunito Bold` and `Japanese` font presets.
- **Atomic Single-Batch Undo & Mid-Operation Rollback:**
  - Record Title/Subtitle updates using the existing metadata model API and `MetadataDelta` (from `core/undo_journal.py`).
  - Commit metadata (Title/Subtitle), Unique Actor speaker renames (unlocked boxes only), and Dialogue text updates inside **ONE atomic Undo batch** with **transaction-level rollback** if any mutation fails mid-operation (a failed import MUST NEVER leave metadata applied while dialogue/actor updates are only partially applied).
  - Preserve immutable JP source keys and enforce Translation Locks.
- **`U-09` Pre-Import Archive Checkbox:**
  - Add checkbox **`Archive the XUAT translation`** inside `ImportFromXUATDialog`, **checked (`True`) by default**.
  - When unchecked, display a clear inline warning explaining the risk of skipping XUAT archiving.
  - **Unchecked Behavior (STRICT):** Import ONLY — leave EVERY XUAT source file on disk 100% untouched; do NOT open `XUAT Translation Archiving`; do NOT archive, delete, or rewrite any source entry. (Never allow this checkbox to bypass mandatory archive-first when destructive cleanup IS executed.)
  - **Checked Behavior:** After a successful import (`applied_count > 0`), close `ImportFromXUATDialog` and launch the asynchronous **`XUAT Translation Archiving`** flow passing ONLY non-speaker applied records (dialogue + title + subtitle) plus protected actor identities.

### 3. `U-08` & `U-10` — Asynchronous `XUAT Translation Archiving` with Batched `ttk.Treeview` (`misora.py`, `core/xuat_cleanup.py`)
- **Rename (`U-10`):** Use **`XUAT Translation Archiving`** consistently for the window title, `Tools -> XUAT Translation Archiving...` menu item, and status notifications (replacing `"Import Complete - Clean up / Archive"`).
- **Asynchronous Non-Blocking Classification Workflow (`U-08`):**
  1. Main thread captures an **immutable snapshot** of document dialogue/metadata data + applied records + protected actor identities + XUAT roots/fingerprints (plus a monotonic task generation token).
  2. Background worker builds/refreshes index (if needed) and runs `classify_cleanup_candidates()` strictly off the main thread with **cooperative cancellation** (`cancel_event`) and **zero Tkinter / live-doc access**.
  3. Main thread polls the queue, rejects stale generation tokens (after document switch, dialog close, or newer scan), and cleanly tears down worker/candidate state on close/cancel/switch.
- **Lightweight Batched `ttk.Treeview` Candidate UI (Anti-Freeze):**
  - Replace the per-candidate `tk.Frame` + `tk.Checkbutton` + multi-`tk.Label` explosion with a single lightweight **`ttk.Treeview`** (interactive check-toggle column `[✓]` / `[ ]`, Tier badge, File:Line, Key/Value preview).
  - **Bounded Main-Thread Batch Population:** Insert Treeview rows in bounded batches (e.g., `50–100` rows per `after()` tick) so even thousands of candidate rows NEVER freeze the UI; abort remaining insertion ticks immediately if dialog closes or generation token changes.
  - Preserve conditional Duplicate Scope radio (hidden when 0 duplicates), Linebreak policy, Archive strategy/dir/ext validation + `.txt`/`Text/` warning, `Debug > Safety` banner, and 2-step empty-file deletion confirmation.

### 4. `U-12` & `U-13` — Cancellable XUAT Discovery & Reliable Unified Progress Controller (`misora.py`, `core/xuat_index.py`)
- **Cancellable File Discovery (`core/xuat_index.py::build_xuat_index`):**
  - Accept optional `cancel_event` and `progress_cb` parameters in `build_xuat_index()`.
  - Check `cancel_event.is_set()` **during recursive directory/file discovery as well as during file parsing** — avoid materializing an unnecessarily large complete file list before cancellation can be observed.
- **Unified Status-Bar Progress Controller (`misora.py`):**
  - Share ONE status-bar progress controller across:
    1. **Project Search** (`on_start_search` / `_run_background_search`),
    2. **Reload XUAT Translations** (move index rebuild off main thread into cancellable background worker),
    3. **XUAT Translation Archiving Scan**.
  - **Reliable Event Delivery Contract (CRITICAL):**
    * Each operation registers a unique `task_id` / generation token with explicit `start`, `progress`, `complete`, `fail`, and `cancel` lifecycle events.
    * **Coalesced Progress, Never Dropped Terminals:** Progress updates MAY be coalesced/replaced per `task_id` to prevent unbounded queue growth, **BUT `start`, `complete`, `fail`, and `cancel` terminal events MUST NEVER be silently dropped** (use separate terminal signaling, reserved terminal slots, or a lock-protected latest-progress map + dedicated terminal event queue).
    * Queue saturation MUST NEVER leave the unified progress bar permanently active; a completed/failed/cancelled task MUST ALWAYS be removed from the active-task registry.
    * **Concurrent Task Isolation:** Finishing or cancelling Task A MUST NOT hide or overwrite Task B while Task B is still active; hide the progress bar only when zero active tasks remain.
    * Ignore stale generation tokens; clean up all task state on `app.destroy()`.
    * Workers NEVER call any Tkinter method.
