==================================================
S1 — STAGED OPEN FILE SAFETY (OPEN-FAILURE-STATE-CORRUPTION)
==================================================
TARGET: `misora.py` -> `MisoraApp.open_file()`

ROOT PROBLEM TO FIX:
1. `open_file()` mutates active application state (`current_file_path`, `is_dirty`,
   `_modified_boxes`, `_original_box_texts`, `_locked_boxes`, `_plain_text_content`, window
   title, `recent_files`, `last_opened_dir`, etc.) BEFORE the target file finishes loading and
   parsing. If loading fails, old document/Unity objects remain paired with the failed file's
   path and wiped metadata/locks.
2. Non-bundle files are read with `encoding="utf-8", errors="replace"`, silently corrupting
   invalid UTF-8 bytes into `U+FFFD` as a successful load.

REQUIRED IMPLEMENTATION:

A. Stage Loading & Strict Decoding in Local Variables
   - Load, decode, and parse the target file into local temporary variables without mutating
     any `self.*` document/UI state beforehand.
   - Reuse existing loaders strictly:
     1. Unity bundles (`.unity3d`, `.asset`): reuse `load_bundle_story()`.
     2. Misora v2 scripts: reuse `StoryDocument.from_v2_text()`.
     3. Ordinary plain-text files: strict UTF-8 decoding (`encoding="utf-8"`, NO
        `errors="replace"`, NO `errors="ignore"`).
   - Invalid UTF-8 (`UnicodeDecodeError`), malformed v2 parse errors, and corrupt bundle errors
     MUST all fail cleanly.

B. Pending Edit Flush on Valid Switch (`AGENTS.md` Rule 13)
   - A previous context exists when `self.current_file_path is not None` (this covers story
     documents AND plain-text files where `current_doc is None`). On the very first open, or
     when no previous context exists, skip the flush entirely — do not crash.
   - Perform the flush ONLY after the target is ready to commit: fresh disk loads after staging
     succeeds, AND cache-hit switches when `reload_from_disk=False`. Do NOT flush before a disk
     load succeeds.
   - Resolve the previous document's story editor widget EXPLICITLY before committing new
     state. Do NOT rely on `focus_get()`: when `open_file()` is invoked from a dock/list click,
     focus can be on a read-only widget such as `txt_opened_files` or `txt_results`, which makes
     `_commit_widget_edit()` silently no-op. Resolution order:
       * if `is_box0_active` -> `txt_box0_summary`
       * elif continuous view and `current_box_idx` in `_card_widgets` -> that card's `txt`
       * elif plain-text fallback in continuous view -> `txt_continuous`
       * else -> `txt_dialogue`
     Guard each with `winfo_exists()`, then call `_commit_widget_edit(that_widget)`.
   - If the flush raises, report through the existing logger/error dialog and return WITHOUT
     committing any new state.
   - Preserve existing explicit `reload_from_disk=True` semantics. If a reload from disk fails,
     keep the previous in-memory document and editor buffer intact.
   - Do not invent a new commit architecture.

C. Commit State Together Only After Success
   - Only after staging succeeds, commit all active document fields together:
     `current_file_path`, `current_doc`, `current_unity_env`, `current_text_obj`,
     `is_bundle_file`, `current_box_idx`, `is_box0_active`, `is_dirty`, `_modified_boxes`,
     `_original_box_texts`, `_locked_boxes`, `_plain_text_content`, plus `last_opened_dir`,
     window title, `recent_files`, `open_documents`, and UI views/status.
   - Preserve the existing `open_documents` cache architecture and cache-hit behavior.
   - Do NOT change how `_original_box_texts` is populated on cache-hit in this slice; the
     UID-keyed Japanese source registry is owned by a later slice.

D. Complete Preservation on Any Failure
   - If loading or parsing fails for any reason, leave previous `current_file_path`,
     `current_doc`, `current_unity_env`, `current_text_obj`, `is_bundle_file`, `is_dirty`,
     `_locked_boxes`, `_modified_boxes`, `_original_box_texts`, `_plain_text_content`,
     `current_box_idx`, `is_box0_active`, visible editor buffer, window title, `recent_files`,
     `last_opened_dir`, and `open_documents` completely unchanged.
   - Do not create or overwrite any `open_documents` entry for the failed file.
   - When `reload_from_disk=True` fails for the CURRENT path, the already-existing
     `open_documents[path]` entry must remain intact (neither deleted nor overwritten).
   - Report the error through existing logger and error dialog mechanisms; keep the app usable.
