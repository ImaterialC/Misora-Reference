### A. Pure-Python Transactional XUAT Cleanup & Archival Engine (`core/xuat_cleanup.py`, `U01`)
Build `core/xuat_cleanup.py` (ZERO Tkinter imports; strictly honoring all XUAT safety invariants):
1. **Strict XUAT Parsing & Format Preservation:**
   - Reuse `read_text_file_strictly()`, `write_atomic_encoded()`, `split_xuat_line()`, and `normalize_xuat_key()`. NEVER decode with `errors='replace'` and rewrite.
   - Preserve exact encoding, BOM (`UTF-8 BOM`/`UTF-16`/`CP932`), line endings (`CRLF`/`LF`), key whitespace, comments (`#`, `//`, `;`), regex directives (`r:`, `sr:`), unchanged lines, and line ordering. NEVER reject short Japanese keys.
2. **Conservative, Auditable 3-Tier Classification (`CleanupCandidate`):**
   - `applied` (*Overwritten / Confirmed Applied*): exact `(file_path, line_number)` entries confirmed successfully applied in the completed `Import from XUAT` run (never includes skipped, locked, missing, or failed boxes).
   - `duplicate` (*Duplicate Key Occurrence*): additional occurrences sharing the exact validated `normalize_xuat_key()` (NOT loose substring matching). Controlled by `duplicate_scope`: `'selected_only'` vs `'all_duplicates'`.
   - `already_translated_unique` (*Conservative Right-Side Match*): for cleaning already-translated `.unity3d` assets whose JP source is no longer in the bundle — current asset raw text equals unescaped right-side XUAT translation value AND that right-side value maps to **strictly 1 unique key** across the XUAT index AND meets safe non-trivial length (`>= 6` non-space chars).
   - `uncertain` (*Ambiguous Right-Side Match*): short/common translations (e.g., `'Yes.'`, `'Got it.'`) or right-side values mapped by `>1` Japanese keys. **Default `selected=False`** — NEVER deleted unless the user explicitly checks them in the preview UI.
3. **Linebreak Policy (`linebreak_policy`):**
   - `'keep_blank_line'` — replaces the removed entry with an empty line, keeping physical line positions intact.
   - `'remove_line_break'` (*Include the line break*) — removes the entire physical line including its newline, leaving no blank gap.
4. **Mandatory Archive Backup of Deleted Entries (`archive_strategy`):**
   - Support two strategies:
     - `'combined'` — appends removed entries into a single combined archive file (e.g. `<archive_dir>/xuat_removed_archive<ext>`).
     - `'per_source_file'` — writes/appends removed entries into `<archive_dir>/<source_stem><ext>` mirroring each source XUAT file (collision-safe append; explicit guard refusing to write if archive target resolves to the same path as any source file!).
   - Preserve complete original `key=value` lines (Japanese key, English value, whitespace, duplicates, encoding/BOM, newline style) preceded by a structured traceability comment block:
     `# [YYYY-MM-DD HH:MM:SS] op=<op_id> | source=<rel_or_name> | story=<story_name> | reason=<applied|duplicate|already_translated>`
   - **Default Archive Location & Extension:** Default directory `<SCRIPT_DIR>/backups/xuat_archive` (OUTSIDE `BepInEx\Translation\en\Text`) and default extension **`.xuat.old`**.
   - Provide helper `validate_archive_target(archive_dir, ext, xuat_roots)` returning explicit warnings whenever `ext.lower() == '.txt'` OR `archive_dir` lies inside any active `BepInEx\Translation\en\Text` root (accurately explaining that XUAT scans `.txt` files in `Text/`, which can reactivate old translations or add BepInEx load overhead while asset redirects hold priority).
5. **Transactional Rewrite & Empty-File Analysis:**
   - Optional ordinary per-file **Safety Backup** before editing each XUAT source file (controlled by `Debug > Safety` preference; uses `make_collision_resistant_backup_path()`).
   - **Transactional write:** Write modified content to same-directory `.tmp` -> re-open and strictly decode/validate line count & syntax -> `os.replace()` onto original ONLY after validation passes. On any error, leave original untouched and return actionable error report.
   - **Empty-File Check (`is_xuat_file_meaningfully_empty()`):** After cleanup, inspect whether ZERO meaningful `key=value` translation entries remain (comments `#`/`//`/`;`, whitespace, and non-entry syntax do NOT count as meaningful entries). Return list of empty files + their exact safety backup path (or `None` if safety backup was disabled). NEVER auto-delete inside the engine without explicit caller command.
