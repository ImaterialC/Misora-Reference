### 1. `U-11` — Complete Exclusion of Global Actor/Speaker Dictionary Entries (`core/xuat_cleanup.py`)
- Strengthen `classify_cleanup_candidates()`:
  1. Global Actor/Speaker dictionary entries MUST be **COMPLETELY EXCLUDED** from the cleanup/archive candidate list — ZERO rows in `analysis.candidates` (do NOT include them even as unchecked `uncertain` rows!).
  2. Never inspect `box.speaker` values as cleanup/archive targets, and if a right-side dialogue match is ambiguous with a known speaker/actor dictionary entry in the document or index, handle conservatively by excluding it from destructive cleanup.
  3. Keep the Actor/Speaker dictionary fully intact and available in `XuatIndex` for `Import from XUAT` matching.

### 2. `U-09` & `U-14` — Redesigned `Import from XUAT` Dialog (`misora.py::ImportFromXUATDialog`)
- **Remove `Include Actor` checkbox** and **exclude Box 0** from the ordinary dialogue list.
- **Separate Metadata & Unique Actor Section (Top of Review List):**
  - Display dedicated paired read-only rows for:
    1. **Title** (`1` row -> applies to Box 0 title metadata).
    2. **Subtitle / Outline** (`1` row when present -> applies to Box 0 subtitle metadata).
    3. **Unique Actors / Speakers** (`1` row per unique speaker name occurring in the document, with `<` / `>` duplicate resolution switcher and Skip checkbox -> applying writes the chosen translation to ALL unlocked dialogue boxes with that speaker name; locked boxes are skipped and clearly reported).
  - Ordinary Dialogue rows appear below, clearly flagging Locked / Skipped / Conflict / Missing states.
- **Uniform Pixel-Exact `54d` Geometry:**
  - Size ALL paired read-only text containers using the shared S09 pixel-exact `54d` measurement helper (+ explicit border/padding allowance; NEVER rely on `tk.Text(width=54)`):
    * Title, Subtitle, and Unique Actor rows: fixed **`1 line × 54d` pixel width**.
    * Ordinary Dialogue rows: fixed **`3 lines × 54d` pixel width**.
  - Verify consistency under both `Global — Nunito Bold` and `Japanese` font presets.
- **Single Atomic Undo Batch:**
  - Applying Import commits Box 0 metadata (Title/Subtitle), Unique Actor speaker updates (unlocked boxes only), and Dialogue text updates inside **ONE atomic Undo batch** (full Undo/Redo restoration, immutable JP source keys preserved, Translation Locks enforced).
- **`U-09` Pre-Import Archive Checkbox:**
  - Add checkbox **`Archive the XUAT translation`** inside `ImportFromXUATDialog`, **checked (`True`) by default**.
  - When unchecked, display a clear inline warning explaining the risk of skipping XUAT archiving.
  - **Unchecked Behavior (STRICT):** Import ONLY — leave EVERY XUAT source file on disk 100% untouched; do NOT open `XUAT Translation Archiving`; do NOT archive, delete, or rewrite any source entry. (Never allow this checkbox to bypass mandatory archive-first when destructive cleanup IS executed.)
  - **Checked Behavior:** After a successful import (`applied_count > 0`), close `ImportFromXUATDialog` and launch the asynchronous **`XUAT Translation Archiving`** flow using only non-speaker applied records (dialogue + title + subtitle).

### 3. `U-08` & `U-10` — Asynchronous `XUAT Translation Archiving` with Batched `ttk.Treeview` (`misora.py`, `core/xuat_cleanup.py`)
- **Rename (`U-10`):** Use **`XUAT Translation Archiving`** consistently for the window title, `Tools -> XUAT Translation Archiving...` menu item, and status notifications (replacing `"Import Complete - Clean up / Archive"`).
- **Asynchronous Non-Blocking Classification Workflow (`U-08`):**
  1. Main thread captures an **immutable snapshot** of document dialogue/metadata data + applied records + XUAT roots/fingerprints (plus a monotonic task generation token).
  2. Background worker builds/refreshes index (if needed) and runs `classify_cleanup_candidates()` strictly off the main thread with **cooperative cancellation** (`cancel_event`) and **zero Tkinter / live-doc access**.
  3. Worker posts coalesced progress events and completion payloads to a bounded/coalescing thread-safe queue.
  4. Main thread polls the queue, rejects stale generation tokens (after document switch, dialog close, or newer scan), and cleanly tears down worker/candidate state on close/cancel/switch.
- **Lightweight Batched `ttk.Treeview` Candidate UI (Anti-Freeze):**
  - Replace the per-candidate `tk.Frame` + `tk.Checkbutton` + multi-`tk.Label` explosion with a single lightweight **`ttk.Treeview`** (with interactive check-toggle column `[✓]` / `[ ]`, Tier badge, File:Line, Key/Value preview).
  - **Bounded Batch Population:** Insert Treeview rows in bounded main-thread batches (e.g., `50–100` rows per `after()` tick) so even thousands of candidate rows NEVER freeze the UI; abort remaining insertion ticks immediately if dialog closes or generation token changes.
  - Preserve conditional Duplicate Scope radio (hidden when 0 duplicates), Linebreak policy, Archive strategy/dir/ext validation + `.txt`/`Text/` warning, `Debug > Safety` banner, and 2-step empty-file deletion confirmation.

### 4. `U-12` & `U-13` — Unified Status-Bar Progress Controller (`misora.py`, `core/xuat_index.py`)
- Implement ONE unified status-bar progress controller (`_ProgressTaskManager` or equivalent on `MisoraApp`) shared by:
  1. **Project Search** (`on_start_search` / `_run_background_search`),
  2. **Reload XUAT Translations** (move index rebuild off main thread into cancellable background worker),
  3. **XUAT Translation Archiving Scan**.
- **Concurrency & Safety Contract:**
  - Each operation registers a unique `task_id` / generation token with explicit `start`, `progress` (determinate or indeterminate + clear task label), `complete`, `fail`, and `cancel` events.
  - **Coalesced/Bounded Progress Updates:** Rapid worker progress updates coalesce per `task_id` rather than growing an unbounded queue.
  - **Concurrent Task Isolation:** Completing or cancelling Task A MUST NOT hide or overwrite Task B if Task B is still active (show active task count or highest-priority active task label; hide progress bar only when zero active tasks remain).
  - **Stale Rejection & Safe Cleanup:** Ignore stale tokens; clean up all task state on completion, failure, cancellation, or `app.destroy()`.
  - Workers NEVER touch Tkinter directly.
