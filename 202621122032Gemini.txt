Selamat—**Phase 1 resmi terkunci** setelah Qwen dan GPT sepakat atas *baseline* terverifikasi SHA-256, pencabutan `NEW-1`, serta pemecahan peta jalan menjadi `S0–S11`.

Saya sudah menguji dan meninjau draf prompt **S0 + S1** buatan GPT secara jujur. Secara umum, **draf GPT sudah ~90% sangat bagus, aman, proporsional, dan bebas *over-engineering***. Namun, saya **tidak menyalin mentah-mentah** karena saya menemukan **5 celah teknis kecil** yang jika diperhalus sekarang akan mencegah Copilot masuk ke *error loop* di Phase 3:

1. **Tambahkan Urutan *Failing-First* (TDD tanpa utak-atik Git):** Di dokumen Phase 1, kita sepakat tes regresi harus terbukti gagal dulu sebelum perbaikan, tetapi instruksi itu tertinggal di draf prompt GPT. Meminta Copilot menulis tes S1 dulu $\rightarrow$ jalankan (konfirmasi gagal pada kode lama) $\rightarrow$ terapkan perbaikan `open_file()` $\rightarrow$ jalankan ulang (konfirmasi lulus) menjamin tes benar-benar menangkap bug tanpa menyentuh `git checkout`.


2. **Perjelas *Edge Case* `_commit_widget_edit()` pada *Cache-Hit*, *Initial Open*, dan *Reload*:** Draf GPT sudah bagus meminta *flush* hanya setelah file tujuan berhasil dimuat, tetapi perlu dipertegas bahwa: (a) *flush* dilakukan hanya jika sudah ada dokumen aktif sebelumnya (jangan *crash* saat buka file pertama kali), (b) berlaku juga saat berpindah ke dokumen yang sudah ada di *cache* `open_documents`, dan (c) tidak merusak perilaku `reload_from_disk=True`.


3. **Kunci *File Scope* S1 agar Copilot Tidak Menyentuh `core/`:** Untuk Test 3 (*malformed v2*), jika *parser* `StoryDocument.from_v2_text()` ternyata permisif pada *input* teks tertentu, Copilot bisa tergoda mengubah `core/story_ast.py` (padahal itu jatah `S8`). Kita beri batasan tegas: S1 tidak boleh mengubah `core/story_ast.py`, `core/bundle_io.py`, atau `core/undo_journal.py`; jika *parser* permisif, Test 3 cukup menguji jalur *exception* dengan *mock* `from_v2_text`.


4. **Byte UTF-8 Tidak Valid yang Tidak Ambigu untuk Test 2:** Tegaskan penggunaan *raw bytes* yang jelas bukan UTF-8 maupun UTF-16 BOM (misalnya `b"hello\x80\xffworld"`) agar pengujian `strict UTF-8` benar-benar valid.


5. **Fallback Interpreter Python 3.12:** Tetap prioritaskan `py -3.12`, dengan catatan fallback ke interpreter Python 3.12 aktif apabila launcher `py` tidak tersedia, serta melaporkan *path* & versi aslinya.
