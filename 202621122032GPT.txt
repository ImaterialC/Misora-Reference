==================================================
S1 — OPEN-FAILURE-STATE-CORRUPTION
==================================================

TARGET:
misora.py

PRIMARY FUNCTION:
MisoraApp.open_file()

CURRENT PROBLEM:

open_file() modifies active application state before
the requested file has been successfully loaded.

Examples include:
- current_file_path
- is_dirty
- _modified_boxes
- _original_box_texts
- _locked_boxes
- _plain_text_content
- Window title
- Recent files
- last_opened_dir

If loading fails, the application may retain an old
document object while its active path and other state
refer to the new failed file.

This creates a dangerous mismatch between the active
document, Unity environment, TextAsset and file path.

A later Save may operate on inconsistent document state.

A second issue:

Non-bundle files currently use:

read_text(encoding="utf-8", errors="replace")

Invalid UTF-8 sequences are silently replaced by U+FFFD.
The file can then be saved with permanently altered text.

==================================================
REQUIRED IMPLEMENTATION
==================================================

A. STAGE DOCUMENT LOADING

Refactor open_file() to load and validate the requested
file using local temporary variables.

Do not modify self.* document state during the loading
and parsing stage.

Handle these formats using the existing architecture:

1. Unity bundles:
   .unity3d
   .asset

   Reuse load_bundle_story().

2. Misora v2 scripts:
   Reuse StoryDocument.from_v2_text().

3. Ordinary text files:
   Use strict UTF-8 decoding.

Do not use errors="replace" or errors="ignore".

Do not introduce another bundle loader or parser.

B. COMMIT APPLICATION STATE ONLY AFTER SUCCESS

Once loading and parsing have completed successfully,
commit the new document state.

The commit must update all relevant active document fields
together, including:

- current_file_path
- current_doc
- current_unity_env
- current_text_obj
- is_bundle_file
- current_box_idx
- is_box0_active
- is_dirty
- _modified_boxes
- _original_box_texts
- _locked_boxes
- _plain_text_content

Also update:
- last_opened_dir
- window title
- recent_files
- open_documents
- corresponding UI views and status.

Preserve the existing cache-hit behavior for documents
already present in open_documents.

Do not replace the existing document cache architecture.

C. FAILED LOAD MUST PRESERVE THE PREVIOUS DOCUMENT

If any loading or parsing operation fails:

- Keep the previous current_file_path.
- Keep the previous current_doc object.
- Keep the previous Unity environment and TextAsset.
- Keep the previous is_dirty state.
- Keep the previous locked-box state.
- Keep the previous modified-box state.
- Keep the previous Japanese source-text cache.
- Keep the previous plain-text model content.
- Keep the previous active box and metadata selection.
- Keep the previous window title.
- Keep the previous recent-files list.
- Keep the previous open_documents entries.
- Do not create a cache entry for the failed file.

Use the existing logger and error dialogs.

The application must remain usable after a failed open.

D. PENDING EDIT COMMIT

AGENTS.md Rule 13 requires pending widget edits to be
committed before navigation.

For a successful switch to another document:

- Reuse the existing _commit_widget_edit() mechanism.
- Flush the previous document's pending edit before
  replacing its active context.
- Do not invent another commit architecture.

Only perform this switch-related flush after the target
document has loaded and parsed successfully.

A failed open must not replace or discard the old editor
buffer.

Do not redesign explicit reload/revert behavior in this
slice. Preserve its existing contract.

E. STRICT ERROR HANDLING

An invalid UTF-8 file must fail to load.

A malformed v2 script must fail to load.

A corrupt bundle must fail to load.

All these failures must preserve the previous active
document state.

Do not silently convert corrupted input into a successful
document load.

REGRESSION TESTS — REQUIRED
==================================================

Add focused tests using the existing test architecture.

Do not introduce a new testing framework.

TEST 1 — FAILED BUNDLE LOAD

1. Open a valid document A.
2. Prepare document B as an existing but invalid bundle.
3. Mock the bundle loader to raise an exception.

5. Verify that A remains completely intact.

TEST 2 — INVALID UTF-8

1. Open valid document A.
2. Create a text file B containing invalid UTF-8 bytes.
3. Attempt to open B.
4. Verify that loading fails.
5. Verify that A remains active and unchanged.

TEST 3 — MALFORMED V2 SCRIPT

1. Open valid document A.
2. Create a malformed Misora v2 script B.
3. Cause parsing to fail.
4. Verify that A remains active and unchanged.

TEST 4 — SUCCESSFUL LOAD REGRESSION

Verify successful loading for:
- Ordinary UTF-8 text.
- Valid Misora v2 script.
- Valid Unity bundle when its fixture and dependencies
  are available.

Existing behavior must remain functional.

TEST 5 — PENDING EDIT PRESERVATION

1. Open document A.
2. Make a widget edit without relying on a subsequent
   KeyRelease event.
3. Successfully open document B.
4. Verify that A's edit was committed to its in-memory
   document before switching.

Also verify that failed attempts to open B do not
replace the previous editor buffer.

TEST 6 — SAVE TARGET AFTER FAILED OPEN

After attempting to open an invalid B while A is active,
verify that the active save target remains A.

Do not allow the failed destination to become the
active save destination.
